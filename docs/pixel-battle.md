# Полотно

Статус на 29 сентября 2026: реализовано и проверено локально, **не выпущено на production**.
Включается отдельно для следующего сезона. По умолчанию `LOOP_PIXEL_BATTLE_ENABLED=false`.

## Смысл и интерфейс

Общий рисунок участников виден приглушённым фоном пяти основных страниц. Кнопка «ПОЛОТНО»
открывает отдельный полноэкранный режим, не шестую вкладку. Возврат — Telegram BackButton;
вне Telegram есть крестик. Прежняя вкладка сохраняется. Финансовый результат имеет приоритет.

Полотно заполняет весь viewport, в том числе на планшете и desktop, без рамки и полей.
Фон основных страниц и режим рисования используют одну cover-проекцию: экран показывает участок
общего рисунка, клетки остаются квадратными. Это полноэкранная поверхность, а не бесконечная
координатная плоскость: размер общего раунда по-прежнему 128×128. Панорамирование не открывает
пустую область за рисунком. Заголовок, масштаб и нижняя панель плавают поверх canvas; safe area
ограничивает кнопки, но не рисунок. Слоганов и постоянных обучающих подписей нет.

На экране — рисунок, выбранный цвет и кнопка постановки пикселя. Нажатие выбирает клетку и
приближает её; перетаскивание двигает рисунок, два пальца или кнопки меняют масштаб. Выбор клетки
не тратит ход. Палитра, правила, команды, архив и модерация раскрываются отдельно. Рисунок цветной,
управление чёрно-белое. Canvas 2D перерисовывается при изменениях, без постоянной анимации.
Фон не перехватывает касания; сбой полотна не блокирует остальное приложение.

В mock-сборке есть демонстрационный рисунок. Production использует только состояние API.
CSS режима явно загружается вместе с Mini App до запуска React; лендинг и control его не получают.
Если этот дополнительный CSS не загрузился, скрывается только полотно, остальные страницы открываются.

## Правила

- 128×128 клеток, 16 цветов, исходный цвет — угольный.
- Первый ход сразу, затем один ход каждые 30 секунд по часам сервера. Ходы не копятся.
- Другой телефон, сессия или новая неделя не сбрасывают ожидание.
- Можно перекрашивать чужое; при одновременных ходах решает порядок сохранения сервером.
- Тот же цвет не расходует ход и не перехватывает владение.
- Кошелёк, взнос, рефералы и PBRICK не нужны и не дают преимуществ.
- Раунд: понедельник 00:00 — следующий понедельник 00:00 МСК. Дальше рисунок неизменяем.
  Новый раунд создаётся при первом обращении. Список архива показывает последние 12 раундов;
  более старые остаются доступны по сохранённым ссылкам.
- Здесь нет денежных призов, платежей, финансовых начислений или автоматических рассылок.

Игра серверная, не on-chain и не полностью децентрализованная. Лимит гарантирован на один
Telegram-аккаунт, не на одного физического человека. Полностью исключить мультиаккаунты и ботов
без дополнительных проверок нельзя. Кошелёк или платёж не используются как условие доступа.

## Отдельный командный счёт

Используются существующие команды без нового лимита состава. Один удерживаемый пиксель за
минуту даёт одно очко. Сервер хранит площадь × миллисекунды, UI показывает целые очки. Частая
перекраска своей клетки не даёт бонуса.

При чужой перекраске уже набранное время сохраняется прежней команде, новое идёт новой. При
выходе из команды старые пиксели остаются за ней, новые относятся к текущему составу. Угольный
цвет при перекраске — обычный ход. Ничьи: точное накопленное время, текущая площадь, стабильный ID.

В списке первые 20 команд и своя, если она ниже. Очки останавливаются в конце недели и не влияют
на командный BANK-рейтинг, LOOP Score, очередь, комиссии и DUEL. Названия команд актуальные:
заморожены пиксели и очки, а не история переименований.

## Данные и границы доверия

Миграция `20260928_0025`, родитель `20260812_0024`, добавляет только семь таблиц:

| Таблица             | Данные                                        |
| ------------------- | --------------------------------------------- |
| `pixel_rounds`      | интервал, единый снимок цветов и ревизия      |
| `pixel_players`     | следующий разрешённый ход пользователя        |
| `pixel_cells`       | текущий автор и команда клетки                |
| `pixel_moves`       | упорядоченный журнал и ключи идемпотентности  |
| `pixel_team_scores` | площадь и накопленное время команды           |
| `pixel_shares`      | неизменяемые JPEG выбранных фрагментов        |
| `pixel_moderation`  | область, причина и время операторской очистки |

Запись блокирует пользователя, затем раунд. После ожидания блокировки время проверяется заново.
Цвет, владение, очки, ревизия и cooldown сохраняются одной транзакцией. Повторный `operation_id`
возвращает прежнюю квитанцию; другое содержимое с тем же ID отклоняется. Старая квитанция не
сбрасывает более новый cooldown. Откат транзакции не тратит ход.

PostgreSQL — источник истины. Redis только будит клиентов после commit. Long poll до 20 секунд
освобождает DB-соединение. Одновременно допускается три ожидания на аккаунт; production ограничен
120 чтениями в минуту. При сбое Redis остаются снимки и DB-проверка ходов. При восстановлении
связи клиент получает полный снимок. Скрытая страница прекращает опрос.

До 512 новых ревизий передаются изменениями; больший разрыв — снимком из 16 384 hex-цифр.
Переставленные или пропущенные ревизии не применяются частично. Публичный снимок не содержит
личности авторов, пользовательские ID или кошельки. Клиент рисует только подтверждённый ход,
а при неоднозначной ошибке сохраняет его UUID для повтора в текущем сеансе и сверяет снимок.
Запись ограничена 15 секундами ожидания, чтение — 30.

## API и карточки

База `/api/v1`; обычные маршруты требуют существующую Telegram bearer-сессию.

| Метод и путь                             | Назначение                                         |
| ---------------------------------------- | -------------------------------------------------- |
| `GET /pixels?round_id=…&after=…&wait=20` | полотно, изменения, личный cooldown                |
| `POST /pixels/moves`                     | `round_id`, UUID `operation_id`, `x`, `y`, `color` |
| `GET /pixels/archive`                    | завершённые раунды                                 |
| `GET /pixels/rounds/{id}`                | снимок раунда                                      |
| `GET /pixels/rounds/{id}/scores`         | независимый командный счёт                         |
| `GET /pixels/rounds/{id}/moderation`     | публичный журнал очисток                           |
| `POST /pixels/share`                     | карточка и prepared message Telegram               |
| `GET /pixels/shares/{token}`             | раунд и координаты ссылки                          |
| `GET /pixel-cards/{token}.jpg`           | публичный JPEG без авторизации                     |
| `POST /control/pixels/clear`             | очистка до 32×32 через существующую control-сессию |

Очистка требует причины и ID операции, обнуляет владение и прекращает начисление за очищенные
клетки; прошлые очки не списываются. Она видна в публичном журнале без личности оператора.
Архив очистить нельзя. Отдельной кнопки в браузерной панели пока нет — используется защищённый API.

Карточка 1080×1080 содержит реальный участок 48×48. Повторная отправка того же фрагмента за
30 секунд использует тот же JPEG; другой фрагмент в это время получает `429`. Ссылка
`startapp=pixel_<token>` открывает нужную область, включая архив; `startapp=pixels` — текущий раунд.
Если Telegram prepared sharing недоступен, отправляется обычная ссылка. Карточки и журнал
автоматически не удаляются: перед масштабированием нужен контроль объёма БД.

## Выпуск и проверки

Нужны миграция до `20260928_0025`, совместимые API/web, явное включение
`LOOP_PIXEL_BATTLE_ENABLED=true` и перезапуск API. Выключение скрывает режим и запрещает новые
ходы/карточки, не удаляя архив и не меняя дедлайн. Для оперативной остановки не откатывать
миграцию: downgrade полностью удаляет pixel-данные.

Изменять контракты, финансовые таблицы, credentials или отправлять рассылку не требуется.
Перед включением проверить доступность JPEG для Telegram и реальную отправку карточки —
локальные тесты не отправляют сообщений людям.

```sh
cd apps/api
../../.venv/bin/pytest tests/test_pixels.py -q
# Только выделенные локальные PostgreSQL/Redis, не URL приложения:
LOOP_PIXEL_TEST_DATABASE_URL=postgresql+asyncpg://127.0.0.1:55439/loop_pixels_test LOOP_PIXEL_TEST_REDIS_URL=redis://127.0.0.1:55440/0 ../../.venv/bin/pytest tests/test_pixels_postgres.py -q
cd ../web
npx vitest run src/features/pixels src/telegram.test.ts src/App.test.tsx src/api.test.ts
npx playwright test e2e/pixels.spec.ts
```

PG-тесты создают случайные схемы только в `loop_pixels_test` и удаляют только их. Без test URL
они пропускаются. Проверены конкурирующие устройства, повторы, создание раунда, дедлайн под
блокировкой, откат, long poll, Redis-лимиты, смена команды, архив и модерация. Миграция проверена
на чистой PostgreSQL и переходом с предыдущей ревизии; новые таблицы совпадают с ORM.
UI проверяется на Chromium/WebKit, 320/390/768 px и с верхней safe area. Инъекция двух касаний
доступна в Chromium; проверка на физическом телефоне пока не проводилась.
